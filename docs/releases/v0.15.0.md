# Limiter 0.15.0

Limiter is a Windows network monitoring and traffic control prototype built with WPF and WinDivert. This release includes the changes since v0.14.2.

## New features

- Set low, normal or high priority per application. Applications with traffic queued at the same time share the configured capacity at approximately 1:2:4 weights.
- Configure download and upload capacity separately in Settings. A value of 0 disables prioritization for that direction; the Priorities switch pauses enforcement without removing saved settings.

## Fixes and improvements

- Refresh the activity view, application details panel and Settings layout, with rule badges and clearer explanations in English and Turkish.
- Hide routine packet counters from the status bar while retaining monitoring and rule-loading errors.

## Installation

1. Run the EXE or MSI installer, run the portable EXE directly, or extract the portable ZIP to a folder.
2. Close any previous Limiter instance, then run Limiter.exe and approve elevation.
3. To use priorities, enter your connection's download and upload capacities in KB/s under Settings and select Apply.

With the ZIP, keep WinDivert.dll and WinDivert64.sys alongside the executable. Windows startup is available only for installations under Program Files.

## Known limitations

- Download packets have already crossed the connection before they can be delayed, so download priority and bandwidth are not guaranteed. UDP packets may be lost.
- Only matched traffic is managed; TCP control packets bypass priority scheduling.
- Traffic control requires Limiter to remain running. Loopback traffic, fragmented packets and IPv6 extension headers are outside the limiting and blocking scope.
- Priority sharing has automated engine coverage, but its effect under real elevated network traffic has not been measured in this release.
