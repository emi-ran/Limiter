# Limiter 0.14

Limiter is a Windows network monitoring and traffic control prototype built with WPF and WinDivert. This release includes the changes since v0.12.

## New features

- NetLimiter-inspired toolbar with global Limiter and Blocker switches. Pause enforcement while monitoring continues and saved rules remain intact.
- Independent download and upload blocking for applications and individual processes. Blocking takes precedence over speed limits.
- Direction switches enable or disable speed limits without clearing their saved values.
- Activity and Rule List views, application search, and a resizable application details panel.
- Clickable sorting headers with a highlighted active column, direction arrows and a description of the current sort order.
- Settings tab with English and Turkish interface languages. The default follows the system language, with English as the fallback for unsupported languages. Language changes apply without restarting.
- Optional start with Windows through a per-user elevated Task Scheduler entry. Disabled by default; no password is stored.

## Fixes and improvements

- Keep the details panel layout stable when global Limiter or Blocker switches change.
- Remove the dotted focus outline around the details scroll area.
- Reserve the "Coming soon" label for Priorities; disabled rule controls no longer display it when no application is selected.
- Save language preferences before updating the interface, and roll back the startup switch if registration fails.

## Installation

1. Extract Limiter-win-x64.zip to a folder.
2. Install the .NET 8 Desktop Runtime for Windows x64 if it is not already installed.
3. Close any previous Limiter instance, then run Limiter.exe and approve elevation.

Keep WinDivert.dll and WinDivert64.sys alongside the executable. Download and upload limits use KB/s (1024 bytes per KB); 0 means unlimited and the minimum positive limit is 16 KB/s.

If start with Windows is enabled and you move the application, turn that option off and on again to update its path. Application rules remain under %LOCALAPPDATA%\Limiter\rules.json; language preferences are stored in settings.json in the same folder. PID rules are temporary.

## Known limitations

- Traffic control requires Limiter to remain open; there is no separate Windows service.
- Priorities is not implemented yet.
- Existing UDP connections may not be matched to a process. IPv6 extension headers, fragmented packets and loopback traffic are outside the limiting and blocking scope.
- Queue overflow drops packets. TCP retransmits; UDP data can be lost, and transfer rates can fluctuate at low limits.
- Automated checks do not cover real desktop interaction, a complete Windows sign-in cycle, or long-running TCP/IPv6 load.
